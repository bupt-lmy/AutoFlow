# AxonFlow 产品需求与路线图

> 版本：v0.1.0 Alpha · 更新：2026-07-16 · 状态：实施中

## 产品定位

AxonFlow 是面向开发者和小型团队的多 Agent 工作流平台。用户可用 YAML 或可视化 DAG 定义任务协作关系，以不同模型和工具完成可观察、可回放的自动化任务。

产品的核心不是让模型无约束地“群聊”，而是将职责、工具权限、交接信息、质量门与终止条件显式放入可控制的工作流中。

## 目标用户与场景

| 用户 | 主要场景 |
|---|---|
| 独立开发者 | 编码、测试、评测、交付的自动化闭环 |
| 小型技术团队 | 可视化管理多模型任务与运行证据 |
| AI 应用开发者 | 验证路由、Supervisor、工具调用和 Remote Agent 集成 |

## 现有能力

| 领域 | 已实现能力 | 状态 |
|---|---|---|
| Agent | YAML/目录式 Persona、工具白名单、记忆、重试、Skill、Remote Agent、工作流 Agent 实体 | 可用 |
| 发现 | Dynamic Agent、按能力/Tools/Skills/Tags 的本地发现、固定 Agent 错误/超时替代 | 可用（本地 ADP-lite） |
| 协议 | AIP-lite 任务状态、数据项、产物、Session/Task ID 与 Prompt 注入 | 可用（内部协议） |
| 编排 | Flat 路由、条件分支、边载荷筛选、扇出、join 汇聚、回路、超时、最大迭代、Supervisor | 可用 |
| 模型 | LiteLLM、模型级参数与 fallback、平台模型配置、加密凭据 | 可用 |
| 工具 | 15 个内置工具与配置式插件工具 | 可用 |
| 平台 | 工作流可视化创建/编辑、YAML、Agent/Skill/模型管理、运行历史、日志、Trace | 可用 |
| 运行 | Web 可配置 Cron/时区/输入、运行时热更新调度、定时运行历史、WebSocket、Webhook、LangSmith | 可用（单进程） |

## 已验证的约束

- 通用 `BaseAgent` 支持局部工具 ReAct，但正常文本回复会产生 `status: success`。
- 因此测试/评测的业务失败不能只写在自然语言回复中；要驱动返工路由，质量门必须由自定义或 Remote Agent 返回 `status: error`。
- `flat` 回路受 `max_iterations` 与 `timeout` 保护；`supervisor` 的动态调度也受相同限制。
- Redis 不可用时会降级为内存消息总线，适合本地开发；跨进程恢复与严格消息持久化不应建立在该降级模式上。
- Cron 配置会持久化并在重启后加载，但停机补跑、多实例选主和分布式调度锁仍属于生产化增强项。

详见 [工作流模式与局部 ReAct](WORKFLOW_PATTERNS.md)。

## 近期优先级

1. **外部 ADP Provider**：在本地发现接口上增加外部目录查询、健康度、身份签名和信任策略。
2. **结构化质量门**：提供测试/评测 Agent 的参考实现，将命令/评测结果稳定映射为路由状态与反馈证据。
3. **闭环模板**：提供需求—编码—测试—评测—交付的可直接运行模板，包含并行评测和汇聚。
4. **可靠性与安全**：补充持久化恢复、消息确认、沙箱、外部副作用确认和生产部署指南。
5. **端到端验证**：补足真实 Remote Agent、外部发现、Supervisor 动态决策和质量闭环演练。

## 成功标准

- 用户可在界面或 YAML 中建立至少包含分支、回路或汇聚的一条工作流，并查看其实时节点状态。
- 一个质量门可基于真实测试/评测结果把任务送往交付或返工，而不会因自然语言歧义误路由。
- 每次模型调用和工具执行都能关联到工作流运行，并在日志/Trace 中定位。
